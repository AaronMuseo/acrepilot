# P0 data dictionary

| Store/table | Meaning and constraints |
|---|---|
| PostgreSQL accounts | UUID owner; unique normalized email/E.164 phone; `development_fixture` verification kind explicitly prevents treating it as real verification |
| challenges | Random UUID, hashed challenge+code, expiry, attempt count, single-use state, creation time; resend index |
| sessions | SHA-256 of random 256-bit token; owner FK, expiry and revoked state |
| records | Globally unique UUID, owner FK/index, positive optimistic version, schema-validated JSONB farm/task, tombstone, update timestamp |
| operations | Owner + operation ID unique; canonical validated operation payload and immutable acknowledgement |
| change_clock | Locked singleton with transactional bigint cursor |
| changes | Commit-ordered cursor, owner FK/index, immutable full record snapshot |
| schema_migrations | Applied migration version, initially 1 |
| SQLite records | Local UUID/version/JSON/tombstone; optimistic version includes queued edits |
| SQLite outbox | AUTOINCREMENT ordering, record ID, immutable operation JSON, optional retained failure acknowledgement |
| SQLite metadata | Owner fence, pull cursor, sync timestamp, non-secret farm draft |
| SQLite resolutions | Both local/server values, explicit choice and timestamp |
| SecureStore | Per-account random SQLCipher key, persistent device UUID, current session, selected language |

`farm` payload: name, default plot UUID, positive/null `areaM2`, null/validated lat-long location, explicit unknown soil/water. `task`: parent farm UUID, stable translation key, completion boolean. Names max 100 characters; area cap 1e9 m² is a defensive input bound, not a farm-size recommendation. No monetary floating-point representation is introduced.

Migration: `apps/api/migrations/001_initial.sql`; repeat application is idempotent in P0. Future changes must use new numbered files and an actual migration runner, never rewrite this schema against real stored records. Local version 1 rejects future versions. Full model in build-plan section 15 is retained, including composite ownership constraints for later normalized entities.

Farm-area revisions (2026-10-12): optional areaHistory on farm JSON contains 2–100 entries with UUID, effectiveDate (YYYY-MM-DD or null for baseline), areaM2 (nullable only for an unknown baseline), and reason (baseline/correction/expansion/reduction). Legacy farms need no backfill. First change captures the previous value with unknown date, then appends the change. Accepted entries cannot be removed or rewritten; changes must append in nondecreasing effective-date order and cannot be future-dated in Africa/Nairobi. Current area equals the latest entry. Draft metadata uses draftAreaRevision:<farm UUID>. No SQLite or SQL column migration is required for this optional validated JSON field.

Plot naming slice: plot JSON has kind=plot, immutable farmId, trimmed 1–100 character name (null means translated Default plot), areaM2=null, soil=unknown and water=unknown. The sync parent check requires a live farm owned by the authenticated account. New farms enqueue farm, default plot and fixture task atomically. Older farms expose their reserved plotId locally without a write during rendering; naming that plot creates its record and normal version conflicts protect concurrent names. selectedPlot:<farm UUID> stores device-local selection; draftPlotName:<farm UUID>:<plot UUID or new> stores an unfinished name. Adding plots does not allocate or increase area. No new SQL columns are needed.

Plot area extension: areaM2 is now positive/null, with optional immutable areaHistory matching farm revisions (2–100 entries). Plot creation starts with unknown area; first measurement captures a null baseline. Legacy virtual defaults enqueue creation and measurement atomically. Measured plot totals exclude unknown values and cannot exceed a known farm area (1e-6 square-metre numeric tolerance). Capacity is checked under the existing server change-clock lock, including farm reductions; concurrent capacity conflicts retain local/server versions for recovery. Plot edits do not revise farm total automatically. Dates do not establish surveyed boundaries or validate overlap; splits and historical lineage remain pending.

condition records (soil slice): immutable UUID snapshot with owned farmId/plotId, observedDate (valid calendar date no later than today in Kenya), soilType unknown/sandy/clay/silty/loam/other, textureNotes and fertilityNotes (trimmed, max 500 characters each), source=self_reported. Separate snapshots preserve history; existing snapshots cannot be rewritten. Legacy plot references materialize in the same local transaction before the snapshot is queued. draftSoil:<plot UUID> retains unfinished values. No SQL schema migration. Lab results, copied provenance and water snapshots remain pending.

waterObservation records: immutable self_reported snapshot linked to owned farmId and plotId, valid past/today observedDate, sourceKnowledge unknown/none/known, unique sources (rainfall/harvestedRain/borehole/river/pipedWater/other), overall reliability unknown/reliable/seasonal/unreliable, sourceNotes and shortageNotes up to 500 characters. Unknown/none requires empty sources and unknown reliability; known requires at least one source. draftWater:<plot UUID> retains unfinished form. Independent of soil snapshots and farm-wide water resource entities, which remain pending.

soilTest snapshot: owned farmId/plotId, observedDate (test date, valid past/today), finite numeric ph between 0 and 14 inclusive, reportReference up to 200 characters, source=user_entered_report. Immutable records retained independently of visual soil observations; no lab verification or recommendation. draftSoilTest:<plot UUID> stores unfinished strings. Other lab analytes, methods and attachments remain pending.

tenure snapshot: immutable owned farmId/plotId, observedDate (effective date no later than today), tenureType unknown/owned/leased, nullable leaseStart/leaseEnd, notes max 500 and self_reported source. Non-leased entries require null lease dates; leased dates must be ordered when both known. Past lease end displays review guidance for the latest dated record; no tasks/reminders or account ownership changes are generated. draftTenure:<plot UUID> persists unfinished form.

Optional tenure.leaseCost is null/absent for unknown cost; only leased records may contain it. Fields: amountMinor (integer, 0–999999999999 KES cents), amountText (original decimal digits, max 2 decimal places, required equality to amountMinor), currency KES, basis acres/hectares/squareMetres/plot, period monthly/yearly/seasonal/wholeLease, areaM2 (positive/null snapshot). Estimates use exact BigInt rational area conversion and half-up rounding to a minor unit, rejecting unsafe result sizes. No automatic conversion between periods or expense/payment posting. Legacy tenure records remain valid without this field.

condition source now supports copied_self_reported with required copiedFrom UUID referencing an immutable condition record from another plot in the same owned farm; fresh self_reported forbids copiedFrom. Copy values remain editable and independently persisted. Server validates source existence/ownership/farm/plot before accepting. observedDate on a copy is the copy-recorded date; original source date is retained on the referenced record. Legacy self-reports remain valid.

plotCondition snapshot: owned farmId/plotId, observedDate valid past/today, slope unknown/flat/gentle/steep, drainage unknown/wellDrained/moderateDrainage/poorDrainage, roadAccess unknown/allWeather/seasonalAccess/noVehicleAccess, notes max 500, source=self_reported. Independent immutable observations do not replace soil/water history. draftPlotCondition:<plot UUID> persists partial form. Categories are self-reported qualitative values, not surveyed gradients or guaranteed access.

waterStorage mutable resource: owned immutable farmId, trimmed name max 100, nullable capacity {amountText (up to 3 decimals), unit litres/cubicMetres, litres positive <=1e12 and equal to parsed input conversion}, unique plotIds max 100 matching live owned plots in the same farm, notes max 500 and self_reported source. Empty links mean unassigned, not all plots. New links to legacy default plots materialize those plots in the local transaction before enqueue. draftWaterStorage:<farm UUID>:<resource UUID or new> retains draft. Existing versioned sync/conflict audit applies; capacity does not measure current water availability.

## WaterSource
Farm-wide mutable self-reported resource: kind=waterSource, immutable farmId, trimmed name (1–100), sourceType (unknown or rainfall/harvestedRain/borehole/river/pipedWater/other), reliability (unknown/reliable/seasonal/unreliable), unique plotIds (up to 100, owned/live/same farm), notes and shortageNotes (up to 500 each), source=self_reported. No inferred current volume, coverage, safety, or conversion from existing observations. Versioned sync and explicit conflict audit preserve conflicting edits. Local draftWaterSource:<farmId>:<id|new> metadata retains unfinished entry per account.

## Irrigation snapshot
kind=irrigation; farmId/plotId owned and matching; observedDate calendar date no later than today; irrigationStatus unknown/none/known. Unique methods: drip/sprinkler/furrow/flood/manualWatering/other. Known requires at least one method and positive-or-null irrigatedAreaM2; none requires no methods and zero area; unknown requires no methods and null area. Areas bounded to 1e9 m². plotAreaM2 is captured from the plot when saving (not inferred historical observation-date area); API requires a matching current/historical plot area. Coverage cannot exceed this snapshot except 1e-6 m² conversion tolerance. Percent display derives from these immutable values only when both known. Records are immutable; each correction adds a new dated entry. notes max500, source=self_reported. draftIrrigation:<plotId> retains raw amount and entry unit per account. Coverage is one total across methods, counting overlapping areas once. No source/storage linkage, water-volume or safety inference.
